# pkg/gate agent notes

HTTP config writes share the transactional reload boundary in `pkg/gate/gate.go`: `GetConfig` returns an opaque version, `ApplyConfig` requires it and may target edits with JSON Merge Patch, and only route changes in an already-enabled Java Lite config are live-safe. Keep `pkg/gate/api_handlers.go` on `Gate.ApplyLiveConfigIfVersion`; broad pointer mutation plus `reload.FireConfigUpdate` can claim startup-bound fields changed when the running listeners and forwarding mode did not.

The Connect runtime Gate starts must never outlive Gate's stop request (`pkg/gate/connect.go`): `stopRunning()` stops and joins it (bounded by `connectStopTimeout`, well below the process collection's 30s grace period) before Gate reports stopped and before a reload replaces it, `trigger()` refuses to start one once Gate's context is done (a config update still in flight at shutdown is delivered to the subscriber the event manager captured before the deferred unsubscribe ran), and the watch client does not begin another attempt after its stop request. Regression coverage: `pkg/gate/connect_stop_test.go`.

Config content is read through `reload.ReadConfigFile` (`pkg/gate/gate.go`), never `os.ReadFile`: an `os.ReadFile` handle shares read and write but not delete, so on Windows it makes an editor's atomic replacement of `gate.yml` fail with `ERROR_SHARING_VIOLATION` for as long as the read is in flight - Gate itself refusing an operator's config save (`pkg/internal/reload/config_read.go`, the share mode #959 already uses for the fingerprint handle). Keep the call sites pinned by `pkg/gate/config_read_contract_test.go` and the Windows measurement in `pkg/internal/reload/config_read_windows_test.go`; the reader also bounds one read at `maxConfigFileBytes` rather than reading an unbounded file.
