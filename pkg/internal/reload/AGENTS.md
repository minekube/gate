# pkg/internal/reload agent notes

Config reload correctness must not rely on fsnotify delivery alone: `pkg/internal/reload/watch.go` reconciles content fingerprints because macOS can miss delete/recreate events. On Windows, fingerprint handles must allow delete sharing or an editor's atomic replacement fails with access denied, so open-handle replacement coverage uses `ReplaceFileW` (`fingerprint_replace_test_windows.go`). Beyond that, replacing the config while the watcher reads it is a platform problem, not a watcher bug: `os.Rename` (MoveFileEx `MOVEFILE_REPLACE_EXISTING`) is refused with `Access is denied` against *any* open handle on the destination, whatever its share mode, and the watcher cannot hash the file without opening it (measured on windows-latest: 1319/3000 write+rename attempts failed with the watcher running, 0/3000 with it stopped). Tests that replace a watched config must therefore retry that transient sharing violation (`replace_config_test_windows.go`) instead of calling `os.Rename` directly - and not via `ReplaceFileW`, which drops the destination name mid-swap and so is reported as a second reload where the burst must coalesce into one. Preserve its single-owner loop and silent-watcher regression coverage when changing debounce or watcher behavior.
